# SQL and NoSQL injection

Priority: high
OWASP: A05:2025 Injection
CWE: CWE-89, CWE-943

## What to look for
SQL built with string concatenation or template strings using request input: `"SELECT * FROM users WHERE id = " + userId`, `` `SELECT ... ${req.query.id}` ``, `db.query("..."+ input)`, `db.execute(req.body.x)`, `knex.raw(...)` with interpolation, Sequelize `sequelize.query()` with concat, Python `cursor.execute(f"SELECT ... {x}")`, `"%s" % user_input`, NoSQL: `db.collection.find({ $where: userInput })`, MongoDB `$ne`, `$gt` operator injection from `req.body`, `findOne({ username: req.body.username, password: req.body.password })` without sanitization.

## Bad examples
```js
db.query("SELECT * FROM users WHERE id = " + req.query.id);
db.query(`SELECT * FROM docs WHERE owner='${req.body.user}'`);
collection.find({ username: req.body.username, password: req.body.password });
```

## How to fix
Use parameterized queries / prepared statements: `db.query("SELECT * FROM users WHERE id = ?", [id])`. Use ORM bind APIs. Validate input type (numeric, UUID, allowlist). Never interpolate user input into SQL/NoSQL. For Mongo, cast to string and disallow objects containing `$` keys.
